GraphRAG Web UI is deployed as release "{{ .Release.Name }}".

1. Reach the app
{{- if .Values.ingress.enabled }}
   Ingress is enabled{{ with .Values.ingress.host }} — https://{{ . }}{{ end }} (make sure ingressClassName matches the cluster's controller).
   Uploads: the ingress carries proxy-body-size {{ add .Values.uploadMaxFileMb 1 }}m (uploadMaxFileMb + 1 MiB slack) so
   files up to UPLOAD_MAX_FILE_MB reach the api; raise the same limit on any extra proxy in front of the cluster.
{{- else }}
   Ingress is disabled — port-forward the web service first:
     kubectl port-forward --namespace {{ .Release.Namespace }} svc/{{ include "graphrag-ui.fullname" . }}-web 8080:80
   → open http://localhost:8080: the web pod serves the SPA and its nginx reverse-proxies /api/;
     the upstream name `api` resolves through the chart's ExternalName alias service to
     {{ include "graphrag-ui.fullname" . }}-api (port-forward that svc separately to debug the API directly).
{{- end }}

2. First sign-in
{{- if .Values.proxyAuth.enabled }}
   Sign in through your identity provider — oauth2-proxy fronts every request and the api
   provisions users from the forwarded identity. The bootstrap admin is a no-op in proxy mode
   (spec 2026-08-27 §5.2): proxyAuth.adminEmails ({{ .Values.proxyAuth.adminEmails | join ", " | default "empty" }})
   is what grants the user_admin + ops roles.
{{- else }}
   Log in with bootstrapAdmin.email / bootstrapAdmin.password from values
   (both empty = no account is created and nobody can log in — set one of the two paths).
   ⚠ The email must be a real routable domain, never .local — login validation rejects special-use domains.
   ⚠ The password must be at least 12 characters and not the .env.example placeholder — the api
     refuses to start otherwise (CrashLoopBackOff with the reason in its log).
{{- end }}

3. Check
     kubectl get pods,svc,pvc -n {{ .Release.Namespace }}
{{- if and .Values.postgresql.enabled (eq .Values.postgresql.image.repository "bitnamilegacy/postgresql") }}

ℹ Bundled PostgreSQL: the default image is the frozen bitnamilegacy/postgresql mirror
  ({{ .Values.postgresql.image.repository }}:{{ .Values.postgresql.image.tag }}) — it pulls, but receives no
  further security patches (Bitnami's 2025 registry reorg removed the public semver tags). For
  production point externalDatabase.url at a managed database, or set postgresql.image.* to a
  maintained source.
{{- end }}
{{- if and .Values.postgresql.enabled (not .Values.postgresql.auth.password) }}

⚠ The bundled PostgreSQL is enabled but postgresql.auth.password is empty —
   DATABASE_URL is assembled at render time from the auth values and cannot connect without one.
   Run helm upgrade with --set postgresql.auth.password=<password>.
{{- end }}
{{- if and (not .Values.postgresql.enabled) (not .Values.externalDatabase.url) }}

⚠ postgresql.enabled=false and externalDatabase.url is unset — the render should already have failed; check your values.
{{- end }}
{{- if and (not .Values.existingSecret) (not .Values.jwtSecret) }}

⚠ jwtSecret is unset — the api refuses an empty or placeholder value at startup (the pod enters
   CrashLoopBackOff with the reason in its log). Run helm upgrade with --set jwtSecret=<random string
   of at least 32 characters>; generate one with: openssl rand -hex 32.
{{- end }}
{{- if not .Values.api.image.repository }}

ℹ api.image / web.image have no repository — the local-testing default names are used
  (graphrag-ui-api / graphrag-ui-web, tag defaults to the chart appVersion {{ .Chart.AppVersion }}).
  Set the registry repository/tag in values for a real deployment.
{{- end }}
{{- if .Values.proxyAuth.enabled }}

ℹ proxyAuth is enabled — access is gated by oauth2-proxy external auth
  ({{ if .Values.proxyAuth.external.url }}external instance {{ .Values.proxyAuth.external.url }}{{ else }}the chart's own Deployment {{ include "graphrag-ui.fullname" . }}-oauth2-proxy{{ end }}).
  proxyAuth.emailDomains is the REQUIRED sign-in allowlist (["*"] = open registration);
  PROXY_ADMIN_EMAILS (proxyAuth.adminEmails) is the break-glass path to the `user_admin` + `ops` roles.
{{- if .Values.proxyAuth.external.url }}
  The external instance owns the sign-in allowlist — restrict the email domains on that instance
  (the chart's proxyAuth.emailDomains has no effect on it).
{{- end }}
{{- end }}
