# R4 — Usability & UI/UX live walkthrough (2026-09-21)

## Intro

**Scope.** The nine-step script of plan §3 R4, walked end to end on a fresh compose stack built
from `main@46b4f23`, in both UI languages (zh-TW first, en-US second) at 1280 × 800 with 1920 ×
1080 captures of the list, documents, overview and graph screens. Every screen was judged against
Nielsen's ten heuristics, the empty / loading / error / success states of each panel, keyboard
operability and focus, colour contrast (measured, not eyeballed), copy consistency between the
two catalogs and the README's terms, and antd usage consistency. R1–R3 findings are the exclusion
list: nothing already filed is re-filed; the R3 "R4 hand-offs" are dispositioned in their own
section with the screenshots they asked for.

**Corpus.** `docs/superpowers/reviews/assets/r4-corpus/` — fifteen factual documents on the
history of computing (Babbage … Intel 4004; 3,830 words, 23.4 KiB), written for this phase and
committed so that phase V reuses the exact set. Indexed once with `standard` (`gpt-4.1` +
`text-embedding-3-large`, the `graphrag init` defaults): 2 m 19 s, `num_documents = 15`.

**Tools run.** Playwright chromium 1.63 (`frontend/node_modules`, headless, `locale` pinned per
run) driven by session-local scripts; `docker compose -p r4 up --build -d` from a `.env` copied
from `.env.example` with a generated `JWT_SECRET`; `psql` and `curl` against the stack for the
facts the screenshots cannot show; a catalog scan for zh-TW punctuation; an in-page contrast
measurement of the antd tokens actually rendered. Screenshots live in
`docs/superpowers/reviews/assets/r4-NN-<step>-{zh,en}[-1920].png` (165 files, 14 MB).

**Host.** Intel Mac (`x86_64`), Docker 29.4.0, Compose v5.1.2, Node v24.18.0.

**No code was changed in this phase.** The tree diff is this document, the corpus, the
screenshots and the plan's §8 row. The stack was torn down afterwards (`docker compose -p r4 down
-v`); `.env` stays on the host (gitignored). One R4-only deviation from the script: no test data
was patched in the database — every screen shows what the product produced on its own.

## Summary

A knowledge manager can complete the whole loop — sign in, create a project, upload a corpus,
set the key, index, ask in four modes, click a citation into the document, rate a batch run and
diff two runs — and every one of those steps works. What gets in the way is that the interface
rarely tells them what to do next, and in three places tells them the wrong thing:

- The **first screen of every new project** is a red error card telling the user to run a full
  index of zero documents (R4-04); after the first index it tells them every document was
  dropped and to "review and re-index" — the P0 R3-01 as the user meets it, with a re-index
  loop and nothing to review (R4-05).
- **Saving settings during an index** opens the "modified by someone else" conflict modal with an
  empty server side and a danger-styled *Overwrite* button; the settings page never says the
  project is frozen (R4-01). **Form mode** shows the model fields empty although the YAML has
  them (R4-02).
- **The "Retrieval tests" landing** is a matrix that cannot be built: no set exists, none can be
  created, the button says *Re-run the set*; the place to simply ask a question is a secondary
  toggle (R4-03). Batch results and `POST /query` never link a citation to its document —
  only the streaming route does (R4-40).

Below those, the product's biggest usability tax is **silence and stale state**: a 76-second
DRIFT wait with a skeleton and no cancel (R4-11); a running job with no elapsed time (R4-26); a
finished run whose "running" banner stays until reload (R4-06); 14 stacked toasts for a bulk
upload (R4-07); un-indexed projects that show "No data" in Explore and "try again later" in the
workbench instead of "run an index first" (R4-15, R3-05); citations rendered as pages of
repeated document text in 3.3 : 1 grey (R4-10, R4-21). Copy is the other systemic item: two
words for "job" in zh-TW, developer vocabulary on user screens, raw role ids on the roles page,
and half-width punctuation in 76 zh-TW strings (R4-19, R4-34, R4-18, R4-20).

**Counts:** 42 findings — P1 6, P2 22, P3 14. Effort: S 39, M 3, L 0. Plus 18 R1–R3 hand-offs
dispositioned with screenshots and 14 "Verified OK" items.
