## How the ranking was made

1. **Severity first** (P0 → P3), using the reviewers' calls with one change (below).
2. **Effort ascending inside a severity** — S before M before L — so the cheap certain fixes lead.
3. **Cluster by area** so one wave stays in one region of the code; a wave is cut when it would
   exceed one session (roughly two M-sized items or eight S-sized ones).
4. **Dependency exceptions** are stated per wave: the two frontend substrate waves (F7, F8) run
   before the P1 UX waves because those waves' fixes would otherwise be rewritten by the substrate
   (plan §2, "small fixes get overturned by later refactors"); F13 (backend API substrate) runs
   before the contract and cleanup waves for the same reason.
5. **Same-fix duplicates** (found independently by two phases) share a wave and are marked
   `same fix as R…` in the `wave` column; both rows flip to `done` with the one PR. The 20 pairs:
   R3-01→R1-67, R1-82→R4-02, R2-13→R1-112, R2-30→R1-111, R2-31→R1-116, R4-06→R1-84,
   R4-25→R3-20, R4-20→R1-23, R4-19→R1-66, R4-33→R1-54, R4-36→R1-58, R2-18→R1-79,
   R2-19→R1-73, R2-20→R1-73, R2-22→R3-04, R2-14→R1-14, R2-37→R1-14, R3-18→R2-04,
   R3-34→R2-23, R2-33→R1-51.
