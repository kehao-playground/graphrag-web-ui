## Summary

**Counts:** P0 0, P1 4, P2 48, P3 66 — **118 findings** (66 original + 52 addendum = 118). Original table after the addendum's six severity raises: P1 3, P2 28, P3 35; addendum table (R1-67..R1-118): P1 1, P2 20, P3 31. Source findings: 70 (4 merged) for the original rows, 132 (/code-review 21, /simplify 111; 50 merged into existing rows, 11 folded into four summary rows) for the addendum — see the Addendum and Crosswalk sections.

What matters most:

- **R1-01 (P1)** — `delete_project` takes no project lock, checks for no active job, and
  `rmtree`s the workspace before the row delete; deleting during an index job strands a running
  graphrag subprocess with no cancel path. Correctness item — carried to R2.
- **R1-67 (P1, addendum)** — `promote()` copies the START snapshot's pre-run
  `attributable_titles` onto the baseline row (`index_snapshots.py:171`) although spec §5.2
  requires the post-run set, so after the first index every hash-matching file reads `skipped`
  and health shows skipped == total. Found by `/code-review high`; no test covers `promote`
  against a real post-run `documents.parquet`. Carried to R2 with the addendum's other
  concurrency items (R1-68, R1-77, R1-90).
- **R1-02 / R1-03 (P1)** — the SPA has no way to create a question set or to tag documents,
  so the Tests pane and the tag filter are dead ends on a fresh project even though the backend
  routes exist. Functionality gaps — carried to R3's spec-vs-shipped matrix.
- **Write-path races and ordering (R1-04..R1-06, P2)** — `settings.yaml` optimistic-lock check
  sits outside the project lock, `_commit_settings` writes the file before the DB rows with no
  flush/rollback, and `set_env_key` reads `.env` before taking the lock. All three are small and
  belong in the same fix.
- **Backend shape cluster (R1-07..R1-12, P2)** — `services/files.py` (758 lines) and
  `services/test_runs.py` mix 8 and 5 responsibilities; the project-permission preamble is
  copied 30 times across 9 route modules; service-error→ApiError mapping is duplicated verbatim;
  seven JSON routes ship with no `response_model`, so the OpenAPI contract has empty 200 schemas
  and the frontend hand-types them.
- **Dependency hygiene (R1-13, R1-14, P2)** — `pandas` is imported directly but never declared;
  the CI `audit` job is silently red on 30 nltk advisories (transitive via graphrag/textblob)
  that Dependabot cannot bump and nobody owns. Judged not reachable by a user of this product,
  but the job has no path to green.
- **Frontend server-state cluster (R1-16..R1-18, P2)** — query keys, `queryFn`s and endpoint
  paths are copy-pasted per component (which is how the never-invalidated `health` key
  happened), and hand-written response literals bypass the `api/types.ts` alias layer.
- **Frontend resilience and copy (R1-19..R1-25, P2)** — no error boundary anywhere (a failed
  lazy chunk blanks the app), SettingsPanel mutations fail silently, the jobs pane shows
  `test_run` rows with raw labels, zh-TW punctuation is mixed, a spec reference leaks into UI
  copy, and `npm run screenshots` is broken (R4 needs it).
- **Enforcement gap (R1-48, P3)** — every layering rule verified here holds today only by
  review; there is no import-boundary test or ruff banned-api config.
