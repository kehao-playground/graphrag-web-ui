## Summary

**Counts:** P0 3, P1 2, P2 10, P3 24 — **39 findings**, plus 17 R1 rows confirmed or amended in
"R1 hand-offs" and a Verified OK list of 30 checks.

What matters most:

- **R2-01 / R2-02 (P0)** — graphrag's configuration loader is the hole in the trust boundary.
  `settings.yaml` `${VAR}` placeholders resolve against the **API process's environment** (in
  process at query time, and again in the index subprocess which inherits `dict(os.environ)`),
  and the workspace `.env` is **merged into that same process environment** by graphrag's
  `load_dotenv(override=False)` at query time. Because every active user may create a project
  and thereby owns one (`projects:create` baseline → `owner` → `project:edit_settings`), any
  account can (a) point `api_base` at a host it controls and read `JWT_SECRET`, `DATABASE_URL`,
  `BOOTSTRAP_ADMIN_PASSWORD` and `PROXY_AUTH_SECRET` off the first LLM request — `JWT_SECRET`
  forges an access token for any user — and (b) plant `OPENAI_BASE_URL` / `HTTPS_PROXY` /
  `SSL_CERT_FILE` in the process environment so **every other project's** queries and index jobs
  send their API keys through the attacker, while project A's `GRAPHRAG_API_KEY` silently
  becomes project B's. The settings validator (`services/settings.py:92`) validates placeholders
  against the same `os.environ` and so accepts the payload. Both need one fix wave: an env
  allowlist for the subprocess, `parse_env_vars=False` + our own substitution scoped to the
  workspace `.env` for the in-process path, and a placeholder check that only admits workspace
  keys.
- **R2-03 (P0)** — the same unvalidated `settings.yaml` also carries graphrag's storage
  sections, and graphrag resolves every `base_dir` with no root confinement: an owner points
  `input_storage.base_dir` at the workspaces root and indexes **every other project's documents
  and `.env` files** into their own artifacts (no LLM key needed for the read), or points
  `output_storage.base_dir` at another project's `output/` and overwrites it. Found by
  `/security-review`; the fix is a schema/containment check in `write_settings` (and at
  enqueue) for the storage, reporting, cache and vector-store sections.
- **R2-04 (P1)** — the shipped nginx has no `client_max_body_size`, so through the compose (and
  Helm web pod) path every upload over **1 MiB** fails with nginx's HTML 413 while the product
  advertises `UPLOAD_MAX_FILE_MB=50`. Reproduced against the real image. CI builds the image but
  never sends a request through it (R2-15).
- **R2-05 / R2-10 (P1/P2)** — local-mode sessions are fragile: two tabs share one refresh token in
  `localStorage`, the server's reuse detection revokes the whole family when the second tab
  presents the already-rotated token, and the client wipes the token on **any** non-2xx refresh,
  so a backend restart (502) or a concurrent tab logs everyone out.
- **R2-06 (P2)** — `graphrag.config.load_config` also `os.chdir`s the API process into the
  workspace; the default relative `WORKSPACES_DIR` breaks after the first query in dev.
- **R2-07 (P2)** — test-run results return raw exception text (`str(exc)[-4000:]`) to every
  project viewer, the one place the A7 no-leak posture is not applied.
- **Concurrency cluster (R2-09, R2-11, R2-12, R2-21, plus R1-01/04/05/06/68/77/90 confirmed)** — the
  job state machine has three small holes (cancel-while-queued still spawns and bumps the
  artifact epoch; `terminate()` after exit; preamble failure leaves `finished_at` NULL) on top of
  the R1 items; they belong in one wave with R1-77/R1-90.
- **Tests (R2-15, R2-34..R2-36, R2-39)** — backend line coverage is 95% once greenlet tracing is on (the naive
  82% is an artefact); the gaps that matter are member removal / role change, the users-route
  error mappings, cancel-while-queued, delete-while-running, and the absence of any request that
  travels through the shipped nginx or a Helm render with `auth.mode=proxy`.

Auth & RBAC
- Every route in `api/*_routes.py` carries a permission check: router-level `get_current_user` on all non-public routers; per-handler `can(...)` with the atom the docstrings name — `project:view` for reads (files list/preview/tags, settings/versions/env GET, jobs list/get/preflight/logs, query, explore, health, question sets/questions GET, matrix, results), `project:edit_content` for uploads/deletes/tags/questions/ratings, `project:run_jobs` for job start/cancel and test-run start, `project:edit_settings` for settings PUT / env PATCH+DELETE / dry-run, `project:manage` for project PATCH/DELETE and member PUT/DELETE, `users:manage` for `/api/admin/*` (users, roles, audit). Row-addressed routes (`/jobs/{id}`, `/jobs/{id}/cancel`, `/jobs/{id}/logs`, `/test-runs/{rid}/results`, `/test-results/{rid}/rating`) resolve the project from the row and 404 (never 403) when unreadable (`test_runs_routes.py:121-132,238-249`). Public: `/api/health`, `/api/ready`, `/api/auth/config`, `/api/auth/login|refresh|logout` (local mode only).
- `can()` semantics match spec §4.1: inactive → False; `projects:create` baseline; `act_any` ⇒ every project atom and `view_any`; `view_any` ⇒ `project:view` only (`domain/permissions.py:29-54`).
- Built-in role ids in `domain/role_catalog.py` equal the migration literals (`654f1c990f8f`); built-ins are `is_system` and immutable (`services/roles.py:126-127,149-150`); scope is immutable on update; permissions are validated against the scope's atom catalog (`roles.py:68-76`); project roles cannot be granted globally (`validate_global_roles`).
- Owner immutability: `set_member`/`remove_member` refuse the owner and refuse granting `ROLE_ID_OWNER` (`services/projects.py:183-188,214-215`).
- Last-user-manager guards on both user PATCH and role PATCH, by atom containment not role name (`roles.py:218-265`, `users.py:144-189`); self role/active change forbidden (`users.py:186-187`).
- JIT provisioning: case-insensitive lookup + lowercased write, `IntegrityError` loser re-reads the winner (`auth.py:52-104`); `PROXY_ADMIN_EMAILS` is authoritative-upward on every resolve (spec decision 7) and case-insensitive (`config.py:39-41`); JIT rows get an unusable password hash so a mode flip cannot log them in locally (`auth.py:49`).
- Proxy trust anchor: exactly-one `X-Proxy-Secret` compared with `hmac.compare_digest` on latin-1 bytes; exactly-one `X-Forwarded-Email` ≤320 chars validated as `EmailStr`; display name truncated to 100 (`deps.py:130-157`); `PROXY_AUTH_SECRET` ≥32 enforced at startup (`config.py:48-52`); oauth2-proxy overwrites injected headers and is the only published port in the overlay (`docker-compose.proxy-auth.yml:16-21`).
- Local trust anchor: `JWT_SECRET` placeholder list + ≥32 chars enforced at startup (`config.py:10,60-74`); HS256 only, `type == "access"` required, `sub` parsed as UUID, user must exist and be active on every request (`deps.py:101-120`).
- `must_change_password` gate: enforced in `get_current_user` and mirrored on the `?token=` SSE path with the same allow-list (`deps.py:22-36,176-179,235-238`); the extra middleware only covers unmounted paths (`main.py:98-133`).
- Passwords: argon2 (`auth.py:21,34-42`); login uses a dummy hash on unknown/inactive users to flatten timing (`auth.py:195-215`); login failures rate-limited per (ip, email) with a bounded key map, monotonic clock (`auth_routes.py:32-72`); success does not count.
- Refresh tokens: 48-byte urlsafe random, stored as sha256, rotated on use, reuse revokes the family, expiry checked, deactivation and password change revoke all (`auth.py:146-192`, `users.py:124-127,138-140`, `auth_routes.py:147-149`); `refresh` re-checks `is_active` (`auth_routes.py:121-125`).

Input handling

Concurrency & jobs
- Freeze: uploads, deletes, bulk delete, settings and `.env` writes take `SELECT … FOR UPDATE` on the project row and re-check for an active index/update job **inside** the lock; enqueue takes the same lock, so an in-flight upload's rename commits before the start snapshot (`project_lock.py`, `files.py:296-311`, `jobs.py:44-52`); tags and test runs do not freeze by design (spec 8). `test_project_freeze.py` covers upload-vs-enqueue, settings-vs-enqueue, env, bulk delete and tagging barriers.
- One active job per project is the partial unique index, and `enqueue` maps its `IntegrityError` to `job_conflict` without a check-then-insert (`jobs.py:53-57`); `MAX_CONCURRENT_JOBS` is a per-pod count-then-claim with `FOR UPDATE SKIP LOCKED` claims (`jobs_repo.py:33-54`, `runner_loop.py:170-177`).
- Cancellation for running jobs: DB flag polled every second in a fresh session, SIGTERM → 30 s → SIGKILL (`runner_loop.py:81-99`, `index_runner.py:93-103`); heartbeat every 10 s, stale after 60 s, reconciled at startup and every 60 s (`runner_loop.py:28-57`).
- Process cleanup on API restart: in-flight children are not drained at shutdown by design (spec §10); in the shipped containers the process tree dies with the container and the next boot's reconcile finalises the rows. (Graceful-shutdown gap is R2-27, not a job-correctness issue.)
- Baseline promotion runs inside the finishing transaction (`jobs_repo.py:113-118`); `capture_start` hashes off the loop and unions the previous baseline's names (`index_snapshots.py:53-89`).
- Disk watermark enforced at enqueue against the workspaces root; cache quota is advisory by spec §10 ("prompt manual cleanup"); job-log and start-snapshot retention sweep daily with the failed-job window; `UPDATE_OUTPUT_KEEP_LATEST` pruned after each successful update and daily (`jobs.py:36-43`, `retention.py`).

SSE, streaming, deploy path
- Both SSE routes: `text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`; pre-stream failures raise before the 200 (`query_routes.py:103-111`); mid-stream failure after chunks yields one fixed `error` frame with `code` (`query.py:271-282`); generators `aclose()` in `finally`.
- nginx: `proxy_buffering off` on `/api/` and `/api/jobs/`, `proxy_read_timeout 3600s`, `X-Forwarded-For` set in both locations; uvicorn `--proxy-headers` with RFC1918 `--forwarded-allow-ips` (`frontend/nginx.conf:23-43`, `backend/Dockerfile`); CSP/`X-Frame-Options`/`nosniff`/`Referrer-Policy` headers present.
- Frame cache validity is `(path, mtime_ns, size)` with LRU byte-budget eviction and a to_thread parquet read (`frame_cache.py`).
- Compose passes no api port to the host; the proxy overlay resets the web port (`docker-compose.proxy-auth.yml:16-21`).

Audit
- Every state-changing route in the spec §5 scope writes exactly one audit row inside the service transaction, `audit()` never commits (`services/audit.py:17-19`): project create/update/delete, member add/change/remove, user create/update/reset, role create/update/delete, file upload/delete/tag/untag, env set/delete, settings update, question set/question CRUD, rating, JIT provisioning and promotion.
