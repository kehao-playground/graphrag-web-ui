# i18n Design (zh-TW + en-US)

Date: 2026-08-24
Status: approved in conversation (scope: error-code mapping; library:
react-i18next; default: browser detection); supersedes the 2026-08-23
hygiene-spec decision that "UI strings and API error details remain
zh-TW by design" — operator-facing deploy output (helm NOTES.txt,
backend logs) stays out of scope.

## 1. Problem

All UI copy is hardcoded zh-TW across 13 components/pages plus the
`api/client.ts` error fallbacks; tests assert the zh-TW strings. Backend
error `detail` values are mixed English (`"user not found"`) and zh-TW
(`"此專案已有進行中的索引任務"`) and the frontend surfaces them
verbatim, so both locales currently show mixed-language errors. There is
no locale switcher, no locale persistence, and antd's built-in component
copy (Popconfirm/Modal/Table) is left at its English default.

User decisions (2026-08-24):

1. Scope includes backend error-code mapping — stable machine codes on
   every user-visible error, localized client-side.
2. Library: react-i18next.
3. Default language: browser detection (`zh*` → zh-TW, else en-US),
   localStorage override, manual switcher.

## 2. Goals

- Every user-visible string exists in both `zh-TW` and `en-US` catalogs;
  no hardcoded copy left in components.
- Manual language switcher (sidebar, above logout); choice persisted in
  localStorage; browser detection for first visit.
- antd internal copy follows the app locale via `ConfigProvider`.
- Every user-visible backend error response carries a stable `code`
   (+ optional `params`); the frontend renders localized text by code and
   falls back to the raw `detail` string when the code is unknown
   (forward compatibility with newer backends).
- Typed i18n keys (compile-time check via `CustomTypeOptions`).
- Existing suites stay green: backend tests keep asserting `detail`
   strings; frontend tests keep asserting zh-TW copy (tests run pinned
   to zh-TW).

## 3. Non-goals

- Server-side translation / `Accept-Language` negotiation — the client
  localizes by code; the wire keeps a human-readable `detail`.
- Additional locales beyond zh-TW/en-US (catalog structure allows them).
- Localizing backend logs, helm NOTES.txt, or other operator output.
- FastAPI's built-in 422 validation errors (`RequestValidationError`
  shape) — the frontend never renders them today; unchanged.
- Translating the graph artifact *data* (entity titles, report text) —
  corpus content is user data, not UI copy.

## 4. Backend: error codes

### 4.1 Wire format

New `ApiError(HTTPException)` subclass + exception handler in
`api/errors.py`. Responses become:

```json
{
  "detail": "此專案已有進行中的索引任務",
  "code": "job_conflict",
  "params": {}
}
```

- `detail` keeps today's exact strings (zh-TW and English alike) —
  backend tests, the frontend `detailOf` verbatim contract, and any old
  client keep working; `code`/`params` are additive fields.
- `params` is omitted when empty; values are JSON scalars (strings /
  numbers) interpolated client-side.
- Plain `HTTPException` raised by third-party code (none user-visible
  today) renders without `code`; the frontend falls back to `detail`.

### 4.2 Code catalog

Every user-visible raise site gets a stable snake_case code. Service
exceptions that currently surface as `str(e)` gain a `code` attribute
(plus `params` where the message interpolates values); where tests pin
the exception type, new typed exceptions subclass it (e.g.
`class SettingsValidationError(ValueError)`) so existing
`pytest.raises(ValueError)` assertions stay green.

Shared / cross-route codes:

| code | status | source | params |
|---|---|---|---|
| `not_indexed` | 409 | explore + query `WorkspaceNotIndexedError` | — |
| `user_not_found` | 404 | users + projects | — |
| `forbidden` | 403 | projects/query `_forbidden` | — |

`auth` (auth_routes, deps): `auth_too_many_attempts` 429,
`auth_invalid_credentials` 401, `auth_invalid_refresh_token` 401,
`auth_wrong_current_password` 400, `auth_not_authenticated` 401,
`auth_invalid_token` 401, `auth_must_change_password` 403,
`admin_only` 403.

`explore` (explore_routes): `explore_unknown_table` 404,
`explore_unsupported_filter` 422, `explore_read_failed` 502,
`explore_row_not_found` 404.

`files` (files_routes + services/files): `file_name_empty`,
`file_name_too_long`, `file_name_unsafe`, `file_name_leading_dot`
(all 400), `file_ext_not_allowed` 400 `{ext, input_file_type}`,
`file_too_large` 413 `{max_mb}`, `quota_exceeded` 413 `{quota_mb}`,
`file_not_found` 404.

`jobs` (jobs_routes + services/jobs): `job_not_found` 404,
`job_conflict` 409, `disk_watermark` 409 `{free_mb}`,
`job_already_finished` 409, `job_invalid_last_event_id` 400.

`projects` (projects_routes + services/projects):
`project_not_found` 404, `init_failed` 500, `member_owner_protected`
400 (both identical "cannot demote or remove the project owner" raises
in `set_member`/`remove_member`), `member_not_found` 404.

`query` (query_routes + services/query, rate_limit):
`query_rate_limited` 429, `query_config_failed` 500, `query_failed`
502, `query_interrupted` (mid-stream SSE event, today
`INTERRUPTED_DETAIL = "查詢中斷"`).

`settings` (settings_routes + services/settings):
`settings_too_large`, `settings_invalid_yaml` `{reason}`,
`settings_invalid_placeholder` (all 400), `version_not_found` 404.

`env` (env_routes + services/env_file): `env_invalid_body`,
`env_key_value_required`, `env_value_too_large`, `env_invalid_key`
`{key}`, `env_value_single_line` (400s), `env_key_not_found` 404.

`users` (users_routes): `email_registered` 409,
`user_self_change_forbidden` 400, `user_last_admin_protected` 400.

`dry_run` (dry_run_routes): `dry_run_failed` 500.

### 4.3 SSE

The query stream's `error` event frame becomes
`{"detail": "查詢中斷", "code": "query_interrupted"}` — same additive
shape as HTTP bodies. Pre-stream failures keep returning plain JSON
error bodies (unchanged mechanics).

## 5. Frontend: react-i18next

### 5.1 Setup

- Dependencies: `i18next`, `react-i18next`,
  `i18next-browser-languagedetector`.
- `src/i18n/index.ts` initializes with `supportedLngs: ["zh-TW",
  "en-US"]`, detection order `localStorage → navigator → fallback
  "zh-TW"`, `nonExplicitSupportedLngs: true` so any `zh*` navigator
  locale resolves to zh-TW and everything else falls back to en-US.
- Detector caches under localStorage key `i18nextLng` (its default).
- Both locale JSONs are bundled (no lazy chunks — two small files).
- Catalogs: `src/i18n/locales/zh-TW.json`, `en-US.json`; keys sectioned
  per feature (`common`, `layout`, `login`, `projects`, `projectDetail`,
  `adminUsers`, `files`, `jobs`, `query`, `explore`, `graph`,
  `settings`, `errors`). `errors.*` mirrors §4.2 exactly (zh-TW values
  = today's zh-TW details; previously-English details get proper zh-TW
  translations, which also fixes the mixed-language zh-TW UI).
- Typed keys via module augmentation (`CustomTypeOptions`), so
  `t("jobs.durationMinutes")` is compile-checked and missing keys fail
  `tsc -b`.

### 5.2 antd wiring

`App.tsx` wraps the tree in `ConfigProvider` with
`locale={lang === "zh-TW" ? antdZhTW : antdEnUS}` (from
`antd/locale/zh_TW` / `antd/locale/en_US`), driven by `useTranslation()`
language. antd has no date-picker usage here, so no dayjs locale wiring
is needed.

### 5.3 Switcher

`Layout.tsx` sidebar, above the logout menu: a `Segmented` control with
`中文 / English`. On change: `i18n.changeLanguage(...)` (detector
persists to localStorage). Dates rendered via `toLocaleString` switch to
the active locale (`new Date(v).toLocaleString(i18n.language)`), so the
chosen language — not the browser — decides date format.

### 5.4 Error surfacing (`api/client.ts`)

`detailOf` / `requireOk` gain one step before the verbatim fallback:

1. `body.code` is a string and `i18n.exists("errors." + code)` →
   `i18n.t("errors." + code, body.params ?? {})`.
2. else `body.detail` string → verbatim (unchanged).
3. else the caller's fallback key → `t(key, {status})`.

Callers pass i18n keys instead of hardcoded zh-TW fallbacks.
`QueryPanel`'s SSE `error` handler maps `code` the same way.
`humanDuration` (JobsPanel) composes translated unit words
(`jobs.durationUnitSecond` etc.) — no plural forms needed (CJK has
none; English "1 min" vs "2 min" reads fine without pluralization).

### 5.5 Copy extraction

Every hardcoded zh-TW string in components/pages/client.ts moves to the
catalogs (~150 keys). `zh-TW.json` values are today's exact copy (tests
depend on it); `en-US.json` is newly translated. Comments in code stay
English per AGENTS.md.

## 6. Tests

Backend (uv run pytest):

- Existing detail assertions unchanged (wire detail is untouched).
- New: a parametrized test asserting each §4.2 route emits the expected
  `code` (representative happy-path-per-code where cheap; the ApiError
  constructor/handler gets its own unit test).

Frontend (npm test):

- `setupTests.ts` imports the i18n init with `lng: "zh-TW"` forced
  (jsdom's `navigator.language` is `en-US` — without pinning, every
  existing zh-TW assertion flips). Existing tests keep passing
  unchanged.
- New tests: switcher toggles rendered copy; `detailOf` maps
  `code` + `params` (both locales) and falls back to `detail` on
  unknown code; `en-US.json` and `zh-TW.json` expose identical key sets
  (deep-equal key tree — catches drift).

## 7. Sequence

1. Backend: `api/errors.py` (ApiError + handler + catalog constants),
   convert raise sites, service exception `code`/`params` attributes,
   SSE error frame; backend tests.
2. Frontend: i18n init + catalogs + typed keys + ConfigProvider +
   switcher; extract copy per component; `detailOf` code mapping;
   pin tests to zh-TW; new tests.
3. Verify: `uv run pytest`, `uv run ruff check`, `npm test`,
   `npx tsc -b --noEmit`, `npm run build`; browser-drive the built app
   through both locales (login, projects, jobs modal, files upload
   error, query error) confirming localized copy end to end.
